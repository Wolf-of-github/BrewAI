1. SUMMARY
────────────────────────────────────────────────────────────────────────────────

BrewAI is an AI-powered resume tailoring SaaS. Users upload their resume and
optionally connect their GitHub profile, paste a job description, and receive a
professionally typeset, LaTeX-compiled PDF resume tailored to that role. The
platform has a freemium billing model via Stripe and is deployed entirely on
Google Cloud Platform, with Firebase for auth and hosting.

  Stack at a glance:
    Frontend      React 19 + TypeScript + Vite + TailwindCSS 4
    Auth          Node.js / Express — JWT, Google OAuth, Firebase custom tokens
    API Gateway   Node.js / Express — authenticated REST API surface
    AI Pipeline   Python / Flask — Gemini 2.5 Flash, LaTeX compilation (tectonic)
    Parsers       Python / Flask — resume PDF/DOCX extraction, GitHub repo scan
    Infra         Terraform on GCP — Cloud Run, Cloud Tasks, GCS, Firestore,
                                     Secret Manager, Memorystore (Redis), VPC
    Hosting       Firebase Hosting — brewai.us / brewai-497502.web.app

2. SERVICES MAP
────────────────────────────────────────────────────────────────────────────────

  frontend-service/
    React SPA deployed to Firebase Hosting.
    Components: Home, Dashboard, ResumeRenderer, Navbar, Profile, StripeCheckout,
                Footer, Privacy, Terms.
    Talks to: Auth Service (sign-in), API Gateway (all resume/billing ops),
              Firestore directly (real-time draft status via onSnapshot).

  auth-service/
    Node.js / Express — Cloud Run (public ingress).
    Verifies Google ID tokens via Firebase Admin SDK, issues a signed 24h JWT +
    a Firebase custom token for Firestore SDK access. Creates / updates the
    user document in Firestore on first sign-in.
    Routes: POST /auth/google, GET /health.
    Secrets: jwt_secret, GOOGLE_CLIENT_ID (Secret Manager).

  api-gateway-service/
    Node.js / Express — Cloud Run (public ingress).
    Single authenticated entry point for all user operations. Verifies JWT on
    every request, then routes to downstream services via direct HTTP or Cloud
    Tasks queues.
    Key route groups:
      Resume CRUD   — upload, list, delete, tailor, tailored list/content/tex
      GitHub        — status, upload, disconnect, OAuth URL, OAuth callback
      Billing       — Stripe checkout, portal, webhook, promo redeem, record ops
      Contact       — Resend email (unauthenticated)
    Secrets: jwt_secret, github_client_id, github_client_secret, stripe keys,
             resend_api_key (Secret Manager via lib/secrets.js).

  resume-parser-service/
    Python / Flask — Cloud Run (internal ingress only).
    Downloads raw PDF/DOCX from GCS, extracts text, runs Gemini to produce a
    structured resume.json, writes it back to GCS, updates Firestore.
    Triggered by: Cloud Tasks queue (enqueued by API Gateway on /resume/upload).
    Secrets: gemini_api_key (Secret Manager).

  github-reader-service/
    Python / Flask — Cloud Run (internal ingress only).
    Calls GitHub API to list user repos, uses Gemini to select the most relevant
    ones, scrapes READMEs, stores github_projects.json in GCS, updates Firestore.
    Triggered by: Cloud Tasks queue (enqueued by API Gateway on /github-id/upload).
    Secrets: GITHUB_TOKEN, gemini_api_key (Secret Manager).

  generative-ai-service/
    Python / Flask — Cloud Run (internal ingress only, VPC egress).
    Core AI pipeline. Receives a generation job from Cloud Tasks:
      1. Fetches resume.json + github_projects.json from GCS.
      2. Detects intent: tweak / projects / full pipeline / revamp.
      3. Calls Gemini to select projects, generate or surgically edit LaTeX.
      4. Scrapes GitHub READMEs if needed.
      5. Compiles LaTeX → PDF via tectonic inside the container.
      6. Uploads .tex + PDF to GCS, updates Firestore draft status.
    Redis (Memorystore): caches multi-turn conversation context per draft
    (project selections, prior prompts, JD).
    Firestore collections: drafts, generative-ai-service-jobs,
                           generative-ai-service-data/stats.
    Secrets: gemini_api_key, github_token (Secret Manager).

  infra/
    Terraform — GCS-backed remote state (brewai-497502-tf-state / infra).
    Modules: secrets, storage, firestore, resume-parser-service,
             github-reader-service, generative-ai-service, api-gateway-service,
             auth-service.
    GCP project: brewai-497502   Region: us-central1.

4. DATA FLOW — FULL USER JOURNEY
────────────────────────────────────────────────────────────────────────────────

  SIGN-IN
    1. User clicks "Sign in with Google"
    2. Firebase SDK opens Google popup → returns ID token
    3. Frontend POSTs ID token to auth-service /auth/google
    4. Auth Service verifies token via Firebase Admin, upserts users/{uid} in
       Firestore, mints 24h JWT + Firebase custom token
    5. Frontend stores JWT in a SameSite=Strict cookie (brew_token)
    6. Frontend calls signInWithCustomToken → unlocks Firestore SDK (onSnapshot)

  RESUME UPLOAD
    1. User selects PDF/DOCX (≤10MB) in Dashboard
    2. Frontend POSTs multipart form to gateway /resume/upload (JWT auth)
    3. Gateway stores raw file in GCS: resumes/{userId}/{fileId}
    4. Gateway writes uploadedResumes/{fileId} doc to Firestore (status=pending)
    5. Gateway enqueues Cloud Task → resume-parser-service /parse
    6. Parser downloads file, extracts text, calls Gemini, writes resume.json to GCS
    7. Parser updates Firestore uploadedResumes/{fileId} status=parsed

  GITHUB CONNECT
    1. User clicks "Connect GitHub"
    2. Gateway /github/oauth/url returns GitHub OAuth URL
    3. User authorises → GitHub redirects with ?code=...
    4. Frontend POSTs code to gateway /github/oauth/callback
    5. Gateway exchanges code for access_token, stores in users/{uid}
    6. Gateway enqueues Cloud Task → github-reader-service /read
    7. Reader calls GitHub API, Gemini selects/summarizes repos
    8. Reader writes github_projects.json to GCS, updates Firestore

  RESUME TAILORING
    1. User pastes job description → POSTs to gateway /resume/tailor
    2. Gateway creates drafts/{draftId} in Firestore (status=processing)
    3. Gateway enqueues Cloud Task → generative-ai-service /tasks/generate
    4. Frontend subscribes to onSnapshot on drafts/{draftId}
    5. Gen-AI service detects intent (new / tweak / projects / revamp):
         new/revamp  → fetch resume.json + github_projects.json from GCS
                     → select relevant GitHub projects via Gemini
                     → scrape selected READMEs
                     → call Gemini to generate full LaTeX resume
         tweak       → fetch existing .tex from GCS
                     → call Gemini to surgically edit only changed sections
         projects    → fetch .tex + github_projects.json
                     → re-select/scrape projects
                     → call Gemini to edit projects section
    6. Service runs tectonic to compile .tex → .pdf
    7. Uploads .tex + .pdf to GCS rendered_resume/{userId}/{draftId}.*
    8. Updates drafts/{draftId} status=completed in Firestore
    9. Frontend onSnapshot fires → loads .tex content → renders in ResumeRenderer

  DOWNLOAD
    1. User clicks Download
    2. Frontend calls gateway /billing/record-download (usage tracking)
    3. Gateway returns signed GCS URL for the compiled PDF
    4. Browser opens PDF directly

  [SEC-3]  GitHub OAuth missing state parameter (CSRF)
    api-gateway-service/src/controllers/githubOAuth.js
    The OAuth URL is built without a random state value. An attacker can initiate
    OAuth with their GitHub account, steal the ?code, and replay it against the
    callback endpoint with a victim's JWT — linking their GitHub to the victim's
    account.
    ACTION: Generate a cryptographic state token, store in Redis with userId,
    validate on callback before exchanging the code.
