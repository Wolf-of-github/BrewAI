1. ARCHITECTURE OVERVIEW
────────────────────────────────────────────────────────────────────────────────

High-level: Microservices on GCP Cloud Run. All services are containerized. The
frontend is a React 19 SPA deployed to Firebase Hosting. Backend services are
all private Cloud Run instances except the api-gateway-service (public ingress).
Async inter-service calls go through Cloud Tasks (not synchronous HTTP), making
them retry-safe.

SERVICES MAP:
  frontend-service/        React 19 + TypeScript + Vite + TailwindCSS 4
  auth-service/            Node.js + Express — Google OAuth, JWT, refresh tokens
  api-gateway-service/     Node.js + Express — Public API surface, all user ops
  generative-ai-service/   Python + Flask — Gemini 2.5 Flash, Redis (Memorystore)
  github-reader-service/   Python + Flask — GitHub GraphQL scanning + summarization
  resume-parser-service/   Python + Flask — PDF/DOCX text extraction + safety check
  infra/                   Terraform (GCP) — Cloud Run, Cloud Tasks, GCS, Firestore,
                                             Secret Manager, Memorystore (Redis)

DATA FLOW (high level):
  Browser
    │  1. Google sign-in via Firebase SDK → ID token
    ▼
  auth-service ──── Firestore (users, refreshTokens collections)
    │  Issues 24h JWT + 7d refresh token
    ▼
  api-gateway-service ──── Firestore (drafts, uploadedResumes, users)
    │  JWT verification on every authenticated route                GCS (raw resumes)
    │
    ├─► Cloud Tasks → resume-parser-service  (PDF/DOCX extraction)
    ├─► Cloud Tasks → github-reader-service  (repo selection + summarization)
    └─► Cloud Tasks → generative-ai-service  (Gemini generation + HTML render)
                              │
                              ├─► Redis (conversation context per draft)
                              └─► GCS  (rendered_resume/{userId}/{draftId}.html)
                                        └─► Firestore (draft.status = completed)
                                                  └─► Frontend onSnapshot listener

REALTIME:
  Frontend gets a Firebase custom token from auth-service (/auth/firebase-token)
  then calls signInWithCustomToken + onSnapshot on drafts/{draftId} to track
  generation status without polling the gateway.

INTER-SERVICE AUTH:
  Cloud Tasks → backend services: OIDC tokens (api-gateway-sa service account)
  Browser → auth-service: Google ID token in body (no auth required to sign in)
  Browser → api-gateway: Bearer JWT in Authorization header
  Browser → Firestore: Firebase SDK with custom token (onSnapshot only)

2. SECURITY ISSUES
────────────────────────────────────────────────────────────────────────────────

[SEC-1] CRITICAL — Plaintext secrets on disk
  Files: infra/terraform.tfvars
         generative-ai-service/.env
  The tfvars file contains live production values for jwt_secret, github_token,
  gemini_api_key, github_client_secret. The .env file duplicates these and is
  NOT in .gitignore. Any accidental `git add .` commits all credentials.
  Action: Rotate ALL secrets immediately. Delete both files. Add *.tfvars and
  .env to .gitignore at repo root. Use terraform.tfvars.example with placeholders.

[SEC-2] HIGH — JWT cookie is not HttpOnly (JS-readable)
  File: frontend-service/src/lib/firebase.ts:49
  Code: document.cookie = `brew_token=${token}; path=/; max-age=86400; SameSite=Strict`
  The JWT is set as a JS-readable cookie. Any XSS payload can exfiltrate it.
  Combined with SEC-3, this is a full session hijack chain.
  Action: Move token storage to an httpOnly cookie set by auth-service response
  headers, or accept the XSS risk by ensuring SEC-3 is fixed first.

[SEC-3] HIGH — dangerouslySetInnerHTML on AI-generated HTML (no sanitization)
  File: frontend-service/src/components/Dashboard.tsx:612
  Code: <div dangerouslySetInnerHTML={{ __html: html }} />
  HTML is fetched from GCS (written by Gemini processing user-controlled JD text
  and GitHub READMEs). A crafted JD could inject <script> tags that Gemini
  faithfully includes in generated HTML, executing in the user's browser.
  SEC-2 + SEC-3 = stored XSS → JWT theft → full account takeover.
  Action: Run html through DOMPurify before setting innerHTML. Or render in a
  sandboxed iframe with sandbox="allow-same-origin" (no allow-scripts).

[SEC-4] HIGH — GitHub OAuth missing state parameter (CSRF)
  File: api-gateway-service/src/controllers/githubOAuth.js:13
  Code: `...authorize?client_id=${GITHUB_CLIENT_ID}&scope=read:user` (no state)
  An attacker can initiate OAuth with their GitHub account, steal the ?code, and
  replay against the callback with the victim's JWT — linking attacker's GitHub
  to victim's BrewAI account.
  Action: Generate a cryptographic state token, store in session/Redis with user
  context, validate on callback before exchanging the code.

[SEC-5] MEDIUM — GitHub access token stored plaintext in Firestore
  File: api-gateway-service/src/controllers/githubOAuth.js:57
  The raw OAuth access_token is stored in users/{userId}.github_access_token.
  Any Firestore data exposure or overly-permissive rules reveals live tokens.
  Action: Encrypt tokens before writing, or use Secret Manager per user (costly).
  At minimum, store only the token hash + expiry and force re-auth when needed.

[SEC-6] MEDIUM — Jinja2 autoescape=False in generative-ai-service
  File: generative-ai-service/app/renderer.py:32
  Code: env = Environment(..., autoescape=False)
  Resume field values from Gemini output rendered into HTML without escaping.
  A malicious name like <img onerror=alert(1)> in Gemini's JSON would render
  unescaped into the GCS HTML file (which then hits SEC-3 in the frontend).
  Action: Set autoescape=True; wrap explicit HTML fragments with Markup().

[SEC-7] MEDIUM — No multer file size limit
  File: api-gateway-service/src/routes.js:19
  Code: multer({ storage: multer.memoryStorage() }) — no limits option
  A user can upload a 1GB file, buffering it in gateway RAM → OOM crash.
  Action: Add limits: { fileSize: 10 * 1024 * 1024 } (10MB) to multer options.
  Also validate on frontend before upload starts.

[SEC-8] MEDIUM — Rate limiting commented out
  File: api-gateway-service/src/controllers/resumeTailor.js:41-60
  The entire per-user FREE_DAILY_LIMIT=3 enforcement block is commented out.
  Free users can currently tailor resumes unlimited times, incurring Gemini costs.
  Action: Uncomment the block and verify the Firestore field (jd_count) resets
  daily. Add a frontend 402 error handler to show an upgrade prompt.

[SEC-9] LOW — simulateUpgrade/simulateDowngrade routes in production build
  File: api-gateway-service/src/controllers/billing.js:89-113
  These are guarded by NODE_ENV === 'production' returning 404, but they are
  still registered. If NODE_ENV is unset, any authenticated user upgrades themselves.
  Action: Remove these routes entirely from production builds, or gate behind
  an admin-only middleware checking a claims field on the user document.

4. ERROR HANDLING GAPS (backend)

[EH-7] CRITICAL (runtime) — renderer.py silently swallows render failure
  File: generative-ai-service/app/renderer.py:56-57
  The render_and_upload function catches all exceptions and logs but does NOT

  Fix: Wrap each in try/catch, return 500 with a structured error body.

[EH-9] MEDIUM — redeemPromo Firestore transaction not guarded
  File: api-gateway-service/src/controllers/billing.js:259-273

5. PERFORMANCE BOTTLENECKS
────────────────────────────────────────────────────────────────────────────────

[PERF-1] No pagination on draft list (api-gateway)
  File: api-gateway-service/src/controllers/tailoredList.js:8-11
  .collection("drafts").where("userId","==",userId).get() — no limit.
  A power user with 500 drafts fetches all 500 on every dashboard load.
  Fix: Add .orderBy("createdAt","desc").limit(20) and implement cursor pagination.
  Also create a Firestore composite index on (userId, createdAt desc).

[PERF-2] Full subcollection read to count jobs (generative-ai-service)
  File: generative-ai-service/app/routes.py:36-38
  Every incoming task reads all job documents under the draft to count them.
  Fix: Use a counter field on the draft doc updated with FieldValue.increment(1)
  when a job is created, and FieldValue.increment(-1) if job is deleted.

[PERF-4] Sequential Gemini calls in github-reader-service
  File: github-reader-service/routes.py:57-64
  Up to 20 README summarizations run sequentially — primary latency source for
  GitHub connect flow. Each Gemini call is ~1-3s; worst case 60s total.
  Fix: Use asyncio.gather or concurrent.futures.ThreadPoolExecutor to run
  summarization calls in parallel (respect Gemini rate limits).

[PERF-6] No GCS lifecycle rules
  File: infra/modules/storage/main.tf
  Old rendered HTML and parsed JSON files accumulate indefinitely.
  Fix: Add lifecycle rule to delete non-current versions after 30 days and
  delete rendered resumes for deleted drafts via the resumeDelete controller
  (check if it also deletes GCS objects — currently unclear).

6. MISSING BEST PRACTICES
────────────────────────────────────────────────────────────────────────────────

[BP-1] Zero tests across the entire codebase
  No unit, integration, or e2e tests in any service. CI/CD is a shell script.
  Fix (long-term): Add pytest for Python services (mock Firestore/GCS with
  google-cloud-testutils). Add Jest + React Testing Library for frontend.
  Add supertest for Node.js services. Prioritize the AI prompt pipeline and
  billing/rate-limit logic as highest value test targets.

[BP-2] Firestore security rules not defined in Terraform
  The frontend uses the Firebase SDK to read drafts/{draftId} directly. If the
  Firestore default rules allow unauthenticated access, any user can read any
  draft. Rules should enforce: allow read if request.auth.uid == resource.data.userId.
  Fix: Add a firestore.rules file to the repo and deploy it via the Firebase CLI
  or a Terraform resource.

[BP-5] Stripe integration is a stub
  File: frontend-service/src/lib/stripe.ts
  All Stripe functions return { success: true } after a fake setTimeout. The
  backend billing routes are implemented with real Stripe SDK calls but the
  frontend never calls them. Users cannot actually subscribe.
  Fix: Wire frontend Stripe calls to the gateway /billing/checkout and
  /billing/portal routes. Add STRIPE_SECRET_KEY, STRIPE_PRICE_ID, and
  STRIPE_WEBHOOK_SECRET to the required env validation in api-gateway/index.js.

[BP-7] No request correlation IDs across async task chain
  When a tailor fails, there's no trace ID linking the gateway log entry →
  Cloud Tasks dispatch → AI service log → Firestore write.
  Fix: Generate a request_id at the gateway and pass it as a Cloud Tasks header
  (X-Request-Id). Each downstream service logs it. This enables log correlation
  in Cloud Logging.

[BP-10] No input length validation on company/role PATCH
  File: api-gateway-service/src/controllers/resumeTailorUpdate.js
  Arbitrary-length strings written to Firestore.
  Fix: Add express-validator or manual checks: company max 200 chars, role max 200.

[BP-STARTUP] RESUME_PARSER_TASKS_QUEUE not set in Terraform but listed in REQUIRED_ENV
  File: api-gateway-service/src/index.js:21 vs infra/modules/api-gateway-service/main.tf
  The gateway validates RESUME_PARSER_TASKS_QUEUE at startup but the Terraform
  module only sets CLOUD_TASKS_QUEUE and GITHUB_READER_TASKS_QUEUE. This would
  cause the container to refuse to start in production.
  Fix: Add RESUME_PARSER_TASKS_QUEUE to the Cloud Run env var block in Terraform.
